# CSV catalog migration and duplicate blob-surface correction

The implementation now writes v2 table rows as BOM-prefixed CSV, reads the per-chunk headers, rejects v1/legacy NDJSON catalogs, and keeps blob containers table-local. Store no longer invokes the separate extraction surface, while explicit extraction reads rows through `CatalogReader`. The targeted interchange suite passes all 253 tests, and the new store workflow regression test passes. Watch for: **confirmed** explicit all-table extraction passes encoded directory names as logical schema/table names, so a v2 catalog containing a name that requires encoding is not extracted successfully.

**Verdict**: NEEDS_CHANGES

## High-level view

The row-format migration now spans the writer, reader, metadata, verifier, and restore path, with explicit refusal of older and legacy NDJSON catalogs.

Store and explicit extraction are separate. The remaining issue is in `BlobExtractor.ExtractAllAsync`, which discovers physical encoded folders but forwards those folder names as if they were the original catalog names.

### Encoded-folder extraction mapping

**New Error [confirmed].** `BlobExtractor.ExtractAllAsync` enumerates physical folders and stores their names as `(schema, table)` at `interchange/src/DatabaseInterchange/Transform/BlobExtractor.cs:56-81`, then creates `BlobExtractionRequest` from those values at `:112-114`. In v2, those values are not necessarily logical names: `CatalogWriter` records the original schema/table names separately from the encoded folder at `interchange/src/DatabaseInterchange/Format/CatalogWriter.cs:526-532`. `CatalogReader.ResolveTableDirectory` first looks up the original `(schemaName, tableName)` pair in the catalog index and only then encodes the supplied names at `CatalogReader.cs:390-409`. Therefore, for a schema or table requiring encoding, `ExtractAllAsync` passes the already encoded name as a new logical name, misses the recorded mapping, re-encodes it, and cannot read the table. This violates the plan's requirement that the explicit extraction path use the v2 table-folder contract for all tables.
